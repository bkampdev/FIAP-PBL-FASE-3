# Como contribuir

1. Aceitar o convite do GitHub e ler sua issue, `docs/contratos.md` e os requisitos.
2. Atualizar a cópia: `git switch main` e `git pull --ff-only`.
3. Criar branch própria, por exemplo `git switch -c feat/issue-2-dados`.
4. Implementar primeiro um exemplo pequeno nos arquivos delimitados; combinar mudanças de campos/retornos com quem consome o módulo.
5. Criar testes úteis de caso normal, fronteira e erro. Executar seu módulo e, quando disponíveis, os testes de integração.
6. Fazer commit, push da branch e abrir PR com referência à issue, comandos, entrada/saída, resultado e limitações. Pedir revisão ao colega indicado.
7. Corrigir achados e integrar após aceite. Não afirmar revisão de outra pessoa sem registro real. Fechar a issue após integração e cumprimento dos critérios.

Todos devem contribuir com código compreendido. Não usar commits vazios para simular participação. Alterações de outro autor devem preservar crédito; integração não transfere autoria do módulo inteiro.

Fluxo sugerido: Backlog → Ready (dependências combinadas) → In progress → In review → Done (aceito e integrado). Sem Project obrigatório: usar comentários na issue para registrar andamento/bloqueios.

Não publicar o material didático local, transcrição integral, credenciais ou arquivos do portal contendo informações pessoais. Os exemplos versionados devem ser sintéticos.
